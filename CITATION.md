# Citation Guide

## Canonical source

A complete citation should include:

- John Kuhles as author;
- the exact canonical title;
- canonical ID from `CANONICAL-INDEX.md`;
- version or publication date;
- repository path;
- immutable commit or release URL;
- SHA-256 checksum.

Example pattern:

> John Kuhles, *[Exact canonical title]*, canonical ID `[ID]`, version `[date/version]`, `[path]`, commit `[SHA]`, SHA-256 `[hash]`.

## Quotation

Quote the source exactly. If a spelling or wording issue matters, keep the canonical quotation intact and discuss the possible correction separately. Do not silently improve the quotation.

## Derived summary or deeper reference

Use a two-link pattern:

1. **Canonical source:** the immutable canonical file.
2. **Derived reference:** the summary, explainer, network page, report, or analysis.

Label the second item **derived**, **working interpretation**, **A.I. synthesis**, or another accurate description. Do not call it canonical unless it has separately completed the canonical publication rule.

Suggested notice:

> This page is a derived reference. It should be checked against the linked canonical source and does not replace John's exact wording.

## Claim boundaries

Canonical means authoritative as to **origin, wording, and version**. It does not automatically make every claim a shared proven fact. Keep source attribution, evidentiary status, interpretation, and agreement separate.
